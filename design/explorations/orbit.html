01 the shape

A slot is a question. A module is one answer.

Below is not an illustration. It is the composition this page's own repository runs on, read from its .scrumia/config.yaml, today.

+ specs Where do specs live, in what shape? scrumia-specs

One directory per feature, files created only when they have something to say, acceptance criteria written first and turned into tests.

+ tracker Where does state live — tickets, columns, PRs? scrumia-github-project

GitHub Issues and Projects. Nothing stateful in the repository, and a hook that refuses the commit which tries.

+ team Which standing roles, with what scope? scrumia-teams

Manager, business, tech — plus a designer contributed by the design module. Each boundary is a line of refusal, and every role toggles by config.

+ discovery How does an idea become scoped work? nothing installed

scrumia-discovery exists and is not installed here. So an idea goes straight to a ticket without a scoping pass, and the agents are told to say that rather than improvise one.

+ implementation How is code written, per app? nothing installed

This product ships markdown. Its two code apps — a static site and a validation script — carry no implementation module, so the instruction is to follow the neighbouring code instead of inventing a doctrine.

+ practices Which cross-cutting practices, per app? nothing installed

None here. TDD, SOLID and TanStack Query are on the shelf; a repository of prose does not need them, and pretending otherwise would cost every agent context it could spend on the work.

+ design Where does the design system live? scrumia-design

Identity, tokens and components as files in the repository. A value the tokens do not carry is a finding, not an exception — including on this page.

Three of the seven are empty. Nothing is faked in their place.

.scrumia/config.yaml

# Which module fills which slot.
# An empty slot = capability absent, owned.
composition:
  specs:     scrumia-specs
  tracker:   scrumia-github-project
  team:      scrumia-teams
  discovery: null   # not installed: say so
  design:    scrumia-design
apps:
  - name: "site"
    implementation: null
    practices: []

03 the marketplace

Twelve answers on the shelf.

Each one is a standard Claude Code plugin: skills, agents, hooks. Install the ones your project needs and leave the rest where they are.

  • kernelscrumia-core

    Reads the active composition and writes it into CLAUDE.md. Fills no slot.

  • no slotscrumia-rules

    Rule sections a project owns: index, guides, decisions. No rule without its why.

  • specsscrumia-specs

    Per-feature specs, acceptance-criteria first. A catalogue of files, not a template.

  • trackerscrumia-github-project

    Issues, sub-issues, board columns, branches and pull requests.

  • teamscrumia-teams

    Standing roles and sprint execution, one isolated worktree per ticket.

  • discoveryscrumia-discovery

    Challenges an idea until it can be split, then ships the specs on a branch.not installed here

  • implementationscrumia-rust

    Invalid states unrepresentable, typed errors per layer, one test per invariant.

  • implementationscrumia-solidjs

    Fine-grained reactivity without React reflexes; behaviour-first component tests.

  • practicesscrumia-tdd

    The cycle operationalised for an agent: the mock boundary, AC-to-test mapping.

  • practicesscrumia-solid

    Five principles, each with its limit. Audits over-application as readily as violation.

  • practicesscrumia-tanstack-query

    Query keys, invalidation, optimistic updates — the server/client boundary.

  • designscrumia-design

    Identity, tokens and components in the repo, plus an audit that reports drift and mutedness alike.

04 install

Two commands, then a conversation.

scrumia-init maps your apps, proposes a composition, offers the install command for each module it needs, and writes the result into your CLAUDE.md. Run it again and it checks instead of overwriting.

Needs git, an authenticated gh for the GitHub tracker, and jq for the guard hook. Init checks all three and tells you what degrades if one is missing.

# add the marketplace, install the kernel
