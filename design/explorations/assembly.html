Sheet 02 Sockets and parts

Seven sockets. You decide what seats in each.

A socket is a question. A module is one answer. An empty socket is a capability the project doesn’t have — and the agents are told so, instead of improvising it.

Where do specs live, in what shape?

One directory per feature, files created only when they have content, acceptance criteria written first and turned into tests.

claude plugin install scrumia-specs@scrumia

Where does state live — tickets, columns, PRs?

GitHub Issues and Projects. Nothing stateful in the repo; a hook enforces it.

claude plugin install scrumia-github-project@scrumia

Which standing roles, with what scope?

Manager, business, tech. Each boundary is a line of refusal. Roles toggle by config.

claude plugin install scrumia-teams@scrumia

How does an idea become scoped work?

Challenge it, split it into features, ship the specs on a branch alongside the issues. Leave this socket empty and an idea goes straight to a ticket — the agents will say so rather than invent a scoping pass.

claude plugin install scrumia-discovery@scrumia

How is code written, per app?

One module per stack: Rust, SolidJS. Each covers tests, principles, layout, and what it refuses.

claude plugin install scrumia-impl-rust@scrumia

Which cross-cutting practices, per app?

TDD, SOLID — each with reference, audit and refactor skills. The implementation module situates them for its stack.

claude plugin install scrumia-practice-tdd@scrumia

Where does the design system live?

Identity, tokens and components as files in the repo; a Claude Design project as the review surface. A value the tokens don’t carry is a finding, not an exception.

claude plugin install scrumia-design@scrumia

.scrumia/config.yaml  — written by scrumia-init

specs:scrumia-specs
tracker:scrumia-github-project
team:scrumia-teams
discovery:~  # socket empty
implementation:scrumia-impl-rust
practices:scrumia-practice-tdd
design:scrumia-design

One socket is empty. Nothing gets faked: the agents are told the capability is absent and say so, instead of improvising it.

Sheet 03 Sequence of operations

One run, end to end. Three points are yours.

Everything below the bus is driven by whatever module sits in the socket. Everything wired to the rail above needs a hand. Swap a module and the line changes shape.

Sheet 05 Assembly instructions

Four lines to a running bench.

claude 
# add the marketplace, install the kernel
/plugin marketplace add tibs245/scrumia
/plugin install scrumia-core@scrumia

# then, in the repo to set up
/scrumia-core:scrumia-init

Prerequisites — git, an authenticated gh CLI for the GitHub tracker, and jq for the guard hook. scrumia-init checks all three and says what degrades if one is missing.

scrumia-init maps your apps, proposes a composition, offers the install command for each module it needs, and writes the composition into CLAUDE.md. Re-running it checks instead of overwriting.
