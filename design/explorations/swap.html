One run, end to end

coral steps need a person — three of seven

  1. 01Human Brief An idea, a problem. Nothing formatted.
  2. 02Agents Scoping Challenge it, split it into features. → issues + specs branch discoveryspecs no discovery module — an idea goes straight to a ticket, unscoped
  3. 03Agents Refinement Roles weigh in, sub-issues per context. → Ready for dev trackerteamspecs
  4. 04Human Sign-off Only where doubt, criticality or risk warrant it.
  5. 05Agents Sprint Non-colliding tickets batched. → To dev teamtracker
  6. 06Agents Build One worktree per ticket. Spec, code, tests, review. → PRs teamimplementationpracticesdesign
  7. 07Human Merge Review the PR, test. → Done tracker
Every swap re-summons the agents: they read the composition again before they touch anything.

03 — where you decide

Three times, it is you.

  1. 01 · BRIEF

    You scope

    The agents challenge the idea; you settle the blocking points. A vague brief has nothing to converge on, and the method exists because of it.

  2. 04 · SIGN-OFF

    You sign off

    Only on what is doubtful, critical or risky. Everything else moves without waiting for you.

  3. 07 · MERGE

    You merge

    The final call stays yours, unless you delegate it in writing.

Everything between those three is agents. That ratio is the product.

discovery — nothing installed
04 — the empty slot

An empty slot is a capability you don't have.

Nothing gets faked. The agents are told the slot is empty, and they say so instead of improvising the missing step — which is the failure mode of every agent that has been handed a vague brief.

This repo runs with discovery empty, on purpose. Its CLAUDE.md reads: “an idea therefore goes straight to a ticket without a scoping pass — say so rather than improvising one.”

05 — the shelf

Twelve shipped.

Each one is a standard Claude Code plugin. Install what the project needs; the kernel writes the resulting composition into your CLAUDE.md.

scrumia-corekernelDescribes the active composition and writes it into CLAUDE.md. Fills no slot, and is required.
scrumia-rulesno slotRule sections a project can own: index, guides, decisions — no rule without its why.
scrumia-specsspecsPer-feature specs, TDD-oriented. A file catalog instead of one document.
scrumia-github-projecttrackerIssues, sub-issues, Projects columns, branches and PRs. Requires gh.
scrumia-teamsteamStanding roles and sprint execution in dynamic workflows. Roles are configurable.
scrumia-discoverydiscoveryChallenges an idea until it can be split, then ships specs on a branch.
scrumia-impl-rustimplementationInvalid states unrepresentable, typed errors per layer, one test per invariant.
scrumia-impl-solidjsimplementationFine-grained reactivity without React reflexes, behaviour-first component tests.
scrumia-practice-tddpracticesThe cycle operationalized for an agent, the mock boundary, AC-to-test mapping.
scrumia-practice-solidpracticesThe five principles, each with its limit. Audits violations and over-applications alike.
scrumia-practice-tanstack-querypracticesQuery keys, options, mutations, testing — the server/client boundary, ported from real monorepo use.
scrumia-designdesignIdentity, tokens and components in the repo. Ships the designer role and an audit that reports drift and mutedness alike.
06 — install

Two commands, then a conversation.

# add the marketplace, install the kernel
/plugin marketplace add tibs245/scrumia
/plugin install scrumia-core@scrumia

# then, in the repo to set up
/scrumia-core:scrumia-init

Prerequisites: git, an authenticated gh CLI for the GitHub tracker, and jq for the guard hook. scrumia-init checks all three and tells you what degrades if one is missing.

scrumia-init maps your apps, proposes a composition, offers the install command for each module it needs, and writes the result into CLAUDE.md. Re-running it checks instead of overwriting.
