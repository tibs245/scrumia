The reference composition. Orange steps need a human; blue steps don't.

Human Brief An idea, a problem. Nothing formatted. —
AI Scoping Challenge, split into features.
→ issues + specs branch discovery
AI Refinement Roles weigh in, sub-issues per context.
→ Ready for dev tracker + team
Human Sign-off Only where doubt, criticality or risk warrant it. —
AI Sprint Manager batches non-colliding tickets.
→ To dev team
AI Build One worktree per ticket. Spec, code, tests, review.
→ PRs team + impl + practices
Human Merge Review the PR, test.
→ Done —
Human — 3 touchpoints Agents — everything else Swap a module, the flow changes.
You scopeThe AI challenges; you settle the blocking points.
You sign offOnly designs that are doubtful, critical or risky.
You mergeThe final call stays yours, unless explicitly delegated.

Slots

A slot is a question. A module is one answer. An empty slot is a capability the project doesn't have — agents adjust accordingly.

specs Where do specs live, in what shape? One directory per feature, files created only when they have content, acceptance criteria written first and turned into tests. scrumia-specs
tracker Where does state live — tickets, columns, PRs? GitHub Issues and Projects. Nothing stateful in the repo; a hook enforces it. scrumia-github-project
team Which standing roles, with what scope? Manager, business, tech. Each boundary is a line of refusal. Roles toggle by config. scrumia-teams
discovery How does an idea become scoped work? Challenge, split into features, ship the specs on a branch alongside the issues. scrumia-discovery
implementation How is code written — per app One module per stack: Rust, SolidJS. Each covers tests, principles, layout, and what it refuses. scrumia-impl-rust · scrumia-impl-solidjs
practices Which cross-cutting practices — per app TDD, SOLID — each with reference, audit and refactor skills. The implementation module situates them for its stack. scrumia-practice-tdd · -solid · -tanstack-query
design Where does the design system live? Identity, tokens and components as files in the repo; a Claude Design project as the review surface. A value the tokens don't carry is a finding, not an exception. scrumia-design
— none — And if you leave a slot empty? Nothing gets faked. The agents are told the capability is absent and say so instead of improvising it — this repo itself runs with discovery empty, on purpose. nothing installed

Install


  
Prerequisites: git, an authenticated gh CLI (for the GitHub tracker), and jq (for the guard hook). scrumia-init checks all three and says what degrades if one is missing.



# add the marketplace, install the kernel
/plugin marketplace add tibs245/scrumia
/plugin install scrumia-core@scrumia

# then, in the repo to set up
/scrumia-core:scrumia-init


  
scrumia-init maps your apps, proposes a composition, offers the install command for each module it needs, and writes the composition into CLAUDE.md. Re-running it checks instead of overwriting.
