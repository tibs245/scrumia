🪢 scrumia-compound-design

Le motif de composants composés, indépendant du framework — documenté côte à côte pour React, Vue, Solid et Angular.

slot · aucun version · 0.1.0

Ce dont il est responsable

Possède le motif de composants composés comme capacité inter-frameworks : un parent expose ses parties par une seule API, les enfants atteignent le parent par contexte (ou son équivalent — provide/inject, signals, un service), et les sous-composants voyagent avec le parent plutôt que d'être éparpillés sur des chemins de modules. Traduit le même principe dans l'idiome de React, Vue, Solid et Angular, avec un document de framework par famille pour que la variation entre les quatre soit visible d'un coup d'œil.

Ce qu'il refuse

Une chaîne de props de trois niveaux ou plus pour l'état du parent — le contexte (ou son équivalent) est le medium pour l'état parent-enfant dans un composé. Des sous-composants exportés depuis un chemin de module séparé. Un composé consommé comme une constellation où les parties apparaissent individuellement plutôt qu'à travers le parent.

L'hypothèse qu'il fait

Présuppose que le motif est le même dans chaque framework et que le mécanisme diffère. Coûte la discipline de documenter la même idée quatre fois dans quatre idiomes — et de refuser un projet qui tente de sauter l'étape de documentation au motif qu'un seul framework suffit.
