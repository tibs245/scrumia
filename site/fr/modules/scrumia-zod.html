🛡️ scrumia-zod

Le schéma fait autorité ; le parsing se fait à la couture.

slot · aucun version · 0.1.0

Ce dont il est responsable

Trois règles de refus qui marquent où la validation appartient : le type se dérive du schéma, jamais réécrit à la main à côté ; le parsing se fait à la frontière de confiance, pas à chaque appel interne ; et un schéma dont un humain lit l'échec porte un message ciblé sur le champ. Livre une compétence zod-audit qui audite une base de code existante contre les trois, et un détecteur de frontières qui classe chaque .parse / .safeParse comme traversant ou interne — le verdict est heuristique et chaque constat le dit.

Ce qu'il refuse

Un type réécrit à la main. Un parse sur une valeur que le compilateur a déjà prouvée. Une frontière côté utilisateur qui échoue avec Entrée invalide : string attendu. Le verdict du détecteur sur un parse qui ressemble à un appel interne est rapporté comme un constat à vérifier par un humain, jamais comme un fait.

L'hypothèse qu'il fait

Présume que le schéma fait autorité et que la documentation de la bibliothèque est la citation de chaque règle — pas d'articles de blog, pas de tutoriels, pas de patterns communautaires. Coûte de la discipline sur chaque site de parse et sur chaque schéma, et le rend en erreurs qui signifient quelque chose pour le lecteur qui les déclenche.
