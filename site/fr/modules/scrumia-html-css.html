♿ scrumia-html-css

Accessible par construction — éléments sémantiques, éléments qui suivent la fonction, tests qui disent ce que l'utilisateur rencontre.

slot · aucun version · 0.1.0

Ce dont il est responsable

Possède la forme du HTML et du CSS d'une application web : un élément sémantique quand les deux expriment la même intention, un widget interactif qui utilise l'élément correspondant à sa fonction, et des tests qui atteignent le composant via getByRole, getByLabelText ou getByText. La capacité s'ancre dans le corpus W3C et MDN, jamais dans l'opinion ; chaque règle cite une source, et la licence accompagne la citation.

Ce qu'il refuse

Pas de <div role="button"> quand un <button> porterait le même contrat gratuitement. Pas de <div> stylé en bouton avec cursor: pointer quand aucune sémantique native ne s'applique. Pas de getByTestId quand un sélecteur basé sur l'accessibilité aurait atteint la même cible.

L'hypothèse qu'il fait

Présume que la couche assistive fait partie du contrat, et n'est pas un audit séparé. Un écran qui se lit correctement pour un utilisateur sighted et échoue pour un lecteur d'écran est un défaut que le système de design ne peut pas attraper, et que la revue visuelle ne voit jamais. Les règles de refus du plugin attrapent la forme qui passerait autrement.
