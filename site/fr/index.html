Slots

Un slot est une question. Un module est une réponse. Ci-dessous, la composition réelle de ce dépôt, lue depuis .scrumia/config.yaml — trois des sept slots sont vides, et rien n'y est simulé.

+ specs Où vivent les specs, sous quelle forme ? scrumia-specs

Un répertoire par feature, des fichiers créés seulement quand ils ont quelque chose à dire, des critères d'acceptation écrits d'abord puis transformés en tests.

+ tracker Où vit l'état — tickets, colonnes, PRs ? scrumia-github-project

GitHub Issues et Projects. Rien de stateful dans le dépôt, et un hook qui refuse le commit qui tenterait de l'être.

+ team Quels rôles établis, avec quel périmètre ? scrumia-teams

Manager, business, tech — plus un designer apporté par le module design. Chaque frontière est une ligne de refus, et chaque rôle se bascule par la config.

+ discovery Comment une idée devient un travail cadré ? rien d'installé

scrumia-discovery existe et n'est pas installé ici. Une idée va donc directement en ticket, sans étape de cadrage, et les agents sont invités à le dire plutôt que d'en improviser un.

+ implementation Comment le code est écrit, par app ? rien d'installé

Ce produit livre du markdown. Ses deux apps de code — un site statique et un script de validation — ne portent aucun module d'implémentation : la consigne est de suivre le code voisin plutôt que d'inventer une doctrine.

+ practices Quelles pratiques transversales, par app ? rien d'installé

Aucune ici. TDD, SOLID et TanStack Query restent sur l'étagère — un dépôt de prose n'en a pas besoin, et prétendre le contraire coûterait à chaque agent du contexte qu'il pourrait consacrer au travail.

+ design Où vit le système de conception ? scrumia-design

Identité, tokens et composants sous forme de fichiers dans le dépôt, synchronisés un par un avec un projet Claude Design. Une valeur que les tokens ne portent pas est un constat, pas une exception — y compris sur cette page.

Installation


  
Prérequis : git, une CLI gh authentifiée (pour le suivi GitHub), et jq (pour le hook de garde). scrumia-init vérifie tous les trois et indique ce qui se dégrade si l'un manque.



# ajouter la place de marché, installer le kernel
/plugin marketplace add tibs245/scrumia
/plugin install scrumia-core@scrumia

# puis, dans le repo à configurer
/scrumia-core:scrumia-init


  
scrumia-init cartographie vos apps, propose une composition, offre la commande d'installation pour chaque module dont il a besoin, et écrit la composition dans CLAUDE.md. Le relancer vérifie au lieu de réécrire.
