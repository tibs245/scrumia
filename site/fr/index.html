Slots

Un slot est une question. Un module est une réponse. Ci-dessous, la composition réelle de ce dépôt, lue depuis .scrumia/config.yaml — deux des sept slots sont vides, et rien n'y est simulé.

+ specs Où vivent les specs, sous quelle forme ? scrumia-specs

Un répertoire par feature, des fichiers créés seulement quand ils ont quelque chose à dire, des critères d'acceptation écrits d'abord puis transformés en tests.

+ tracker Où vit l'état — tickets, colonnes, PRs ? scrumia-github-project

GitHub Issues et Projects. Rien de stateful dans le dépôt, et un hook qui refuse le commit qui tenterait de l'être.

+ team Quels rôles établis, avec quel périmètre ? scrumia-teams

Manager, business, tech — plus un designer apporté par le module design. Chaque frontière est une ligne de refus, et chaque rôle se bascule par la config.

+ discovery Comment une idée devient un travail cadré ? scrumia-discovery

scrumia-discovery est installé ici. Une idée passe par un cadrage avant de devenir un ticket : scrumia-brainstorm ouvre la question, scrumia-split découpe ce qui en sort en issues.

+ implementation Comment le code est écrit, par app ? rien d'installé

Ce produit livre du markdown. Ses deux apps de code — un site statique et un script de validation — ne portent aucun module d'implémentation : la consigne est de suivre le code voisin plutôt que d'inventer une doctrine.

+ practices Quelles pratiques transversales, par app ? rien d'installé

Aucune ici. TDD, SOLID et TanStack Query restent sur l'étagère — un dépôt de prose n'en a pas besoin, et prétendre le contraire coûterait à chaque agent du contexte qu'il pourrait consacrer au travail.

+ design Où vit le système de conception ? scrumia-design

Identité, tokens et composants sous forme de fichiers dans le dépôt, synchronisés un par un avec un projet Claude Design. Une valeur que les tokens ne portent pas est un constat, pas une exception — y compris sur cette page.

Composez votre équipe

Sept emplacements, sept décisions — y compris celles que vous laissez vides exprès. Le même index que plus haut, sauf qu'ici c'est vous qui répondez : les lignes écrivent vos commandes d'installation et le .scrumia/config.yaml que scrumia-init vérifiera.

Vide : les agents suivent le code voisin — comportement normal, pas un manque. Le coût arrive au premier fichier d'une nouvelle stack, là où il n'y a aucun voisin à suivre.

+ practices Quelles pratiques transversales, par app ? scrumia-practice-tdd scrumia-practice-solid scrumia-practice-tanstack-query rien d'installé

Vide : aucune discipline transverse n'est imposée. Rien ne fait passer les tests d'abord ni ne garde un motif cohérent d'une app à l'autre — ce que le module d'implémentation ne dit pas, personne ne le dit.

# puis, à l'intérieur du repo à configurer
/scrumia-core:scrumia-init

.scrumia/config.yaml commitez-le, puis scrumia-init le vérifie au lieu de redemander 

# Généré par le compositeur — relisez, puis commitez
project:
  name: your-project
  repo: you/your-repo   # remplacez ces deux lignes par les vôtres

composition:
  specs: scrumia-specs
  tracker: scrumia-github-project
  team: scrumia-teams
  discovery: scrumia-discovery
  design: scrumia-design

apps:
  - name: api
    path: apps/api
    type: backend
    implementation: scrumia-impl-rust
    practices: [scrumia-practice-tdd]
  - name: web
    path: apps/web
    type: frontend
    implementation: scrumia-impl-solidjs
    practices: [scrumia-practice-tdd]

Les pratiques s'appliquent app par app, et seulement aux types d'app dont elles parlent. Là où l'une contredit le module d'implémentation, c'est le module d'implémentation qui gagne.

Modules

Douze livrés. Chacun est un plugin Claude Code standard — installez ce dont vous avez besoin.

🧩 scrumia-core kernel

Décrit la composition active et l'écrit dans CLAUDE.md. Ne remplit pas de slot.

disponiblerequis2 compétences
/plugin install scrumia-core@scrumia
⚖️ scrumia-rules no slot

Sections de règles qu'un projet peut posséder : index, guides, décisions — pas de règle sans sa justification.

disponible4 compétences
/plugin install scrumia-rules@scrumia
📐 scrumia-specs specs

Specs par feature, orientées TDD. Un catalogue de fichiers au lieu d'un seul document.

disponible3 compétences
/plugin install scrumia-specs@scrumia
📋 scrumia-github-project tracker

Issues, sous-issues, colonnes Projects, branches et PRs. Nécessite gh.

disponible5 compétences1 hook
/plugin install scrumia-github-project@scrumia
👥 scrumia-teams team

Rôles établis et exécution des sprints dans des flux de travail dynamiques. Les rôles sont configurables.

disponible3 agents2 compétences
/plugin install scrumia-teams@scrumia
💡 scrumia-discovery discovery

Conteste une idée jusqu'à ce qu'elle puisse être divisée, puis livrez les specs sur une branche.

disponible2 compétences
/plugin install scrumia-discovery@scrumia
🦀 scrumia-impl-rust implementation

Les états invalides sont irreprésentables, erreurs typées par couche, un test par invariant — plus une compétence d'audit pour le code existant.

disponible2 compétences
/plugin install scrumia-impl-rust@scrumia
⚛️ scrumia-impl-solidjs implementation

Réactivité granulaire sans réflexes React, tests de composants axés sur le comportement — plus une compétence d'audit.

disponible2 compétences
/plugin install scrumia-impl-solidjs@scrumia
🔴 scrumia-practice-tdd practices

Le cycle opérationnalisé pour un agent, la limite des mocks, la correspondance AC → test. Référence, audit, refactorisation.

disponible3 compétences
/plugin install scrumia-practice-tdd@scrumia
🧭 scrumia-practice-solid practices

Les cinq principes, chacun avec sa limite. Audite les violations et les sur-applications. Référence, audit, refactorisation.

disponible3 compétences
/plugin install scrumia-practice-solid@scrumia
🔄 scrumia-practice-tanstack-query practices

Query keys, options, mutations, testing — 9 guides, 13 décisions, portés d'une utilisation réelle monorepo.

disponible1 compétences
/plugin install scrumia-practice-tanstack-query@scrumia
🎨 scrumia-design design

Identité, tokens et composants dans le dépôt, synchronisés un à un avec Claude Design. Fournit le rôle designer et un audit qui rapporte la dérive et la fadeur à parts égales.

disponible
claude plugin install scrumia-design@scrumia

Installation

Prérequis : git, une CLI gh authentifiée (pour le suivi GitHub), et jq (pour le hook de garde). scrumia-init vérifie tous les trois et indique ce qui se dégrade si l'un manque.

# ajouter la place de marché, installer le kernel
/plugin marketplace add tibs245/scrumia
/plugin install scrumia-core@scrumia

# puis, dans le repo à configurer
/scrumia-core:scrumia-init
